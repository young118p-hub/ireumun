## 1단계 — 결제 신뢰성 (2026-09-23)

| 무엇 | 왜 |
|---|---|
| 순서: 서버 `prepare` → Play 결제 → 서버 `verify`(Play Developer API) → **기기 저장 → 그다음 소비** (B-1, B-4) | 플러그인 기본값 `autoConsume: true`는 결제가 들어오자마자 소비했다. 저장 전에 앱이 꺼지면 돈만 나가고 결과는 영영 못 받았다. `autoConsume: false`로 바꾸고 저장 뒤 직접 소비 (결제 SDK는 그대로) |
| 검증·저장 실패 시 소비하지 않음, 다음 실행 때 `restorePurchases`로 이어받음 | 미소비 구매는 다시 들어온다. 서버 `verify`는 같은 영수증에 같은 결과를 줘서 여러 번 불려도 안전. 끝내 줄 게 없으면 미확인 결제라 Play가 3일 뒤 자동 환불 |
| 결제할 때 계정 ID를 `obfuscatedAccountId`로 넣고 서버가 대조, 영수증 토큰은 한 번만 | 남의 영수증 재사용 방지 |
| "구매가 완료되었습니다"는 **검증 끝난 뒤에만** (B-3) | `buyConsumable`의 true는 "결제 창이 열렸다"는 뜻일 뿐이었다 |
| 진단 추가 이름(₩9,900)은 **검증 뒤 서버가 생성** | 예전엔 결제 창만 열려도 이름을 먼저 받아서, 취소해도 공짜로 가져갔다 |
| 묶음 할인은 결제 전 작명·진단이 **둘 다 있을 때만** 결제 창 (B-2), 서버 `prepare`도 한 번 더 막음 | 결과 없이 묶음을 사면 소모성이라 돈만 사라졌다. 홈 이용권 화면도 결제할 결과가 없으면 버튼 비활성 + 이유 안내 |
| 무료 체험은 서버 `devices` 테이블에 기기 단위로 (B-5) | 예전 서버 확인 주소는 `YOUR_PROJECT` 그대로였고 함수도 없어서 재설치하면 다시 생겼다. 게다가 기기 ID로 쓰던 `androidInfo.id`는 **빌드 번호**(Build.ID)라 같은 펌웨어 기기끼리 값이 같았다 → `android_id` 패키지로 진짜 ANDROID_ID |
| '내 결과'에서 결과 열기 (결제한 건 전체, 오프라인 가능) | "상세 보기 기능 준비 중"뿐이라 결제하고 화면을 나가면 다시 볼 방법이 없었다 |
| 앱 시작 때 `me`로 서버 결과를 기기에 채움 (지운 결과는 되살리지 않음) | 기기 저장이 날아가도 같은 계정이면 복원. 재설치(익명 계정 교체) 뒤 복원은 계정 연결(구글 등)이 필요 → 나중 단계 |
| 가격은 `Prices` 한 곳: **작명 ₩7,900**, 진단 ₩4,900, **묶음 ₩10,900**, 추가 이름 ₩9,900 | 홈 ₩11,900 / 결제 버튼 ₩7,900으로 서로 달랐다(A-7). 조건대로 낮은 쪽으로. 묶음은 예전 ₩14,900이면 따로 사는 것(₩12,800)보다 비싸져서 기존 할인폭(₩1,900)을 유지해 ₩10,900으로 맞춤. **Play Console 가격도 이 값으로 등록해야 함** |
| 무료 체험 배너의 "가족 사주 분석까지!" 삭제 (A-8) | 무료 체험은 본인 사주라 가족 분석이 없다. 결제 문구에 없는 걸 약속하면 환불 사유 |
| 절입일 연주·월주 버그: 출생 시각(KST)의 태양 황경으로 판정 | 하루 단위(UT 정오 / 입춘의 UT 날짜)로 판정해서 절입일 시각 전 출생이 틀렸다(예: 2021-02-03 10시 → 신축년 신축월, 맞는 값 경자년 기축월). 계산식(Meeus 황경, 오호결월 등)은 그대로 |
